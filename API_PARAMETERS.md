## Обзор

Параметры позволяют управлять поведением генерации текста AI-моделями GLM. С их помощью можно настраивать:

- **Креативность vs Точность** — баланс между разнообразными и предсказуемыми ответами
- **Длину ответов** — ограничение на количество токенов в генерируемом тексте
- **Режим мышления** — включение цепочки рассуждений для сложных задач
- **Потоковую передачу** — получение ответов в реальном времени

Все параметры реализованы в классе `ChatRequestParameters` в пакете `ru.assistant.aicwl.chat.data`.

## Описание параметров

### do_sample

**Тип:** `Boolean`
**По умолчанию:** `true`
**API имя:** `do_sample`

Определяет, использовать ли семплирование для увеличения разнообразия ответов.

| Значение | Описание | Когда использовать |
|----------|----------|-------------------|
| `true` | Случайное семплирование на основе вероятности. Модель может выбирать не только наиболее вероятные токены, но и менее вероятные варианты. | Творческие задачи, генерация идей, рассказов |
| `false` | Жадная стратегия (greedy decoding). Всегда выбирается токен с наивысшей вероятностью. | Технические задачи, код, факты, стабильность |

**Пример:**

```kotlin
val params = ChatRequestParameters(
    doSample = false  // Детерминированные ответы для кода
)
```

### temperature

**Тип:** `Float`
**Диапазон:** `0.0 - 2.0`
**По умолчанию:** Зависит от модели (обычно 0.7-0.9)
**API имя:** `temperature`

Контролирует случайность выхода при семплировании.

#### Значения

- **0.0 - 0.3**: Консервативные, детерминированные ответы
  - Модель выбирает только наиболее вероятные токены
  - Ответы сосредоточенные и предсказуемые
  - Идеально для: кода, технической документации, фактов

- **0.4 - 0.7**: Сбалансированные ответы
  - Разнообразие при сохранении релевантности
  - Подходит для большинства задач
  - Идеально для: деловой переписки, аналитики, инструкций

- **0.8 - 1.0**: Креативные, разнообразные ответы
  - Модель рассматривает более широкий спектр токенов
  - Ответы менее предсказуемые
  - Идеально для: творческого текста, мозгового штурма

- **> 1.0**: Экстремально случайные ответы
  - Часто не связанные с контекстом
  - Используйте с осторожностью

#### Взаимодействие

- Рекомендуется использовать **только один** из параметров: `temperature` ИЛИ `top_p`
- При использовании вместе с `top_p`, эффект `temperature` усиливается

**Пример:**

```kotlin
val params = ChatRequestParameters(
    temperature = 0.2f  // Консервативные ответы
)
```

### top_p

**Тип:** `Float`
**Диапазон:** `0.0 - 1.0`
**По умолчанию:** Зависит от модели (обычно 0.8-0.9)
**API имя:** `top_p`

Контролирует разнообразие через nucleus sampling (top-p sampling).

#### Как работает

Модель сортирует все возможные токены по вероятности и берёт минимальный набор токенов, сумма вероятностей которых достигает значения `top_p`.

#### Значения

- **0.1 - 0.3**: Очень консервативные
  - Узкий круг наиболее вероятных токенов
  - Высокая предсказуемость
  - Для: кода, технических задач

- **0.5 - 0.7**: Сбалансированные
  - Разнообразие при сохранении качества
  - Для: деловой переписки, инструкций

- **0.8 - 0.95**: Разнообразные
  - Широкий спектр токенов
  - Для: креативных задач

- **1.0**: Полное отключение nucleus sampling
  - Рассматриваются все токены

#### Взаимодействие

- Используйте **только один** из параметров: `top_p` ИЛИ `temperature`
- `top_p = 0.1` → почти всегда предсказуемые ответы
- `top_p = 0.9` → более творческие ответы

**Пример:**

```kotlin
val params = ChatRequestParameters(
    topP = 0.9f  // Разнообразные ответы
)
```

### max_tokens

**Тип:** `Int`
**По умолчанию:** Зависит от модели (обычно 65536)
**API имя:** `max_tokens`

Ограничивает максимальное количество токенов в генерируемом ответе.

#### О токенах

Один токен примерно соответствует:
- **4 символам** английского текста
- **2-3 символам** русского текста
- **0.75 слова** в среднем

#### Рекомендации по длине

| Количество токенов | Примерное количество слов | Использование |
|-------------------|-------------------------|---------------|
| 128 - 512 | ~100 - 400 слов | Короткие ответы, факты, определения |
| 1024 - 2048 | ~750 - 1500 слов | Объяснения, инструкции, решения |
| 4096+ | ~3000+ слов | Подробные руководства, анализ, генерация кода |

#### Ограничения по моделям

| Модель | По умолчанию | Максимум |
|--------|--------------|----------|
| glm-4.7 | 65536 | 131072 |
| glm-4.6 | 65536 | 131072 |
| glm-4.5-air | 65536 | 98304 |

**Пример:**

```kotlin
val params = ChatRequestParameters(
    maxTokens = 2048  // Средняя длина ответа
)
```

### stream

**Тип:** `Boolean`
**По умолчанию:** `false`
**API имя:** `stream`

Определяет режим передачи ответа от API.

#### Режимы

**`false` (полный ответ):**
- API возвращает полный ответ целиком после генерации
- Проще в обработке
- Пользователь ждёт дольше первого отображения

**`true` (потоковый режим):**
- API возвращает ответ через Server-Sent Events (SSE)
- Токены поступают постепенно по мере генерации
- Эффект "печатания" в реальном времени
- Более сложная реализация клиента

#### Когда использовать

**`stream = true`:**
- Интерактивные чат-интерфейсы
- Когда важна мгновенная обратная связь
- Длинные ответы, которые пользователь читает по мере генерации

**`stream = false`:**
- Пакетная обработка
- API-интеграции, где ответ обрабатывается целиком
- Когда простота реализации важнее UX

**Пример:**

```kotlin
val params = ChatRequestParameters(
    stream = true  // Потоковый режим для чата
)
```

### thinking

**Тип:** `ThinkingConfig`
**По умолчанию:** `ThinkingConfig(type = "enabled")`
**API имя:** `thinking`

Параметры включения режима "цепочки рассуждений" (Chain-of-Thought reasoning).

#### Как работает

1. Модель генерирует внутренний монолог ("thinking content")
2. Анализирует задачу и рассматривает варианты
3. На основе анализа формирует финальный ответ для пользователя

#### Поддержка моделей

- ✅ GLM-4.5 и выше
- ❌ Более старые модели (параметр игнорируется)

#### Типы режима

| Тип | Описание | Когда использовать |
|-----|----------|-------------------|
| `enabled` | Режим мышления активирован | Сложные задачи, требующие рассуждений |
| `disabled` | Стандартный режим | Простые вопросы, быстрые ответы |

#### Когда использовать thinking

✅ **Рекомендуется для:**
- Математических задач и вычислений
- Логических головоломок
- Анализа сложных сценариев
- Многошагового планирования
- Отладки кода и поиска ошибок
- Задач на причинно-следственные связи

❌ **Не рекомендуется для:**
- Простых вопросов фактического характера
- Генерации текста по шаблону
- Быстрых ответов, когда скорость важнее качества

**Пример:**

```kotlin
val params = ChatRequestParameters(
    thinking = ThinkingConfig.enabled()  // Включить режим мышления
)
```

## Предустановки

Для удобства использования предусмотрены готовые предустановки параметров для различных сценариев.

### Creative (Творческая)

```kotlin
val params = ChatRequestParameters.creative()
```

**Характеристики:**
- Высокая креативность и разнообразие
- `doSample = true`, `temperature = 0.8`
- `maxTokens = 2048`
- `thinking = enabled`

**Для:** Генерации идей, историй, вариантов решений, мозгового штурма.

### Technical (Техническая)

```kotlin
val params = ChatRequestParameters.technical()
```

**Характеристики:**
- Высокая детерминированность и точность
- `doSample = false`, `temperature = 0.2`
- `maxTokens = 4096`
- `thinking = enabled`

**Для:** Кода, технической документации, фактов, SQL-запросов.

### Balanced (Сбалансированная)

```kotlin
val params = ChatRequestParameters.balanced()
```

**Характеристики:**
- Баланс между креативностью и точностью
- `doSample = true`, `temperature = 0.5`
- `maxTokens = 2048`
- `thinking = enabled`

**Для:** Большинства повседневных задач, деловой переписки, инструкций.

### Fast (Быстрая)

```kotlin
val params = ChatRequestParameters.fast()
```

**Характеристики:**
- Максимальная скорость генерации
- `doSample = false`, `temperature = 0.1`
- `maxTokens = 512`
- `thinking = disabled`

**Для:** Простых вопросов, фактов, определений, когда скорость важнее качества.

## Примеры использования

### Пример 1: Генерация кода

```kotlin
val params = ChatRequestParameters.technical().copy(
    maxTokens = 4096,  // Достаточно места для кода
    thinking = ThinkingConfig.enabled()  // Включить рассуждения
)

val request = ChatCompletionRequest(
    model = "glm-4.7",
    messages = listOf(
        ChatMessage(role = "user", content = "Напиши функцию быстрой сортировки на Python")
    ),
    parameters = params
)
```

### Пример 2: Творческий рассказ

```kotlin
val params = ChatRequestParameters.creative().copy(
    temperature = 0.9f,  // Ещё больше креативности
    maxTokens = 2048
)

val request = ChatCompletionRequest(
    model = "glm-4.7",
    messages = listOf(
        ChatMessage(role = "user", content = "Напиши короткий фантастический рассказ о путешествии к звёздам")
    ),
    parameters = params
)
```

### Пример 3: Математическая задача

```kotlin
val params = ChatRequestParameters.technical().copy(
    temperature = 0.1f,  // Минимум случайности
    thinking = ThinkingConfig.enabled(),  // Важно для рассуждений
    maxTokens = 2048
)

val request = ChatCompletionRequest(
    model = "glm-4.7",
    messages = listOf(
        ChatMessage(role = "user", content = "Реши уравнение: x³ - 6x² + 11x - 6 = 0")
    ),
    parameters = params
)
```

### Пример 4: Быстрый ответ на простой вопрос

```kotlin
val params = ChatRequestParameters.fast()

val request = ChatCompletionRequest(
    model = "glm-4.5-air",  // Быстрая модель
    messages = listOf(
        ChatMessage(role = "user", content = "Какая столица Франции?")
    ),
    parameters = params
)
```

### Пример 5: Кастомные параметры

```kotlin
val params = ChatRequestParameters(
    doSample = true,
    temperature = 0.6f,  // Свое значение
    topP = null,  // Не используем top_p
    maxTokens = 1500,  // Кастомная длина
    stream = false,
    thinking = ThinkingConfig.enabled()
)

params.validate()  // Проверка параметров
```

## Рекомендации по выбору

### Выбор между temperature и top_p

| Сценарий | Рекомендуемый параметр | Значение |
|----------|----------------------|----------|
| Код, технические задачи | `temperature` | 0.1 - 0.3 |
| Креативный текст | `temperature` | 0.8 - 1.0 |
| Общая задача | `top_p` | 0.8 - 0.95 |
| Стабильные ответы | `top_p` | 0.1 - 0.3 |

**Правило:** Используйте только **один** из параметров, не оба одновременно.

### Выбор max_tokens

| Тип задачи | Рекомендуемое значение |
|-----------|----------------------|
| Короткий факт | 128 - 512 |
| Определение, объяснение | 512 - 1024 |
| Инструкция, решение | 1024 - 2048 |
| Подробное руководство | 2048 - 4096 |
| Генерация кода | 2048 - 4096 |
| Анализ, статья | 4096+ |

### Выбор модели и параметров

| Модель | Характеристики | Рекомендуемые параметры |
|--------|---------------|----------------------|
| **glm-4.7** | Самая мощная, медленная | `technical()` для сложных задач |
| **glm-4.7-flash** | Сбалансированная, быстрая | `balanced()` для повседневных задач |
| **glm-4.5-air** | Самая быстрая, менее точная | `fast()` для простых вопросов |

### Выбор thinking режима

✅ **Включайте (`enabled`) для:**
- Математических вычислений
- Логических задач
- Многошагового планирования
- Отладки кода
- Анализа сложных сценариев

❌ **Отключайте (`disabled`) для:**
- Простых вопросов фактов
- Генерации по шаблону
- Максимальной скорости

## Валидация параметров

Класс `ChatRequestParameters` включает метод `validate()` для проверки параметров:

```kotlin
val params = ChatRequestParameters(
    temperature = 0.5f,
    topP = 0.9f
)

try {
    params.validate()
} catch (e: IllegalArgumentException) {
    println("Ошибка: ${e.message}")
}
```

**Проверяемые ограничения:**
- `temperature`: 0.0 - 2.0
- `topP`: 0.0 - 1.0
- `maxTokens`: >= 1
- `n` (количество попыток): >= 1
